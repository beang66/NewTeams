# 결정 기록

코드만 보고는 이유를 알기 어려운 결정을 날짜순으로 남긴다. 새 결정은 아래에 덧붙인다.

## 2026-11-02 — 검수 세션 이어 쓰기

- **결정:** 태스크 검수 2회차부터 GPT 검수자는 같은 Codex 세션을 이어(`codex exec resume`) 지난 검수 이후 diff만 받는다(`prompts/reviewer-followup.md`). OpenAI 예비 실행기는 세션을 모르므로 요청마다 전체 프롬프트(`freshPrompt`)를 함께 두고, 넘어갈 때 그것을 보낸다. 세션 ID를 못 받은 회차 다음은 다시 전체 검수.
- **이유:** smoke 실행 실측 캐시 비율이 dev 94.5%, 검수자 12.7%. 검수자는 매 회차 새 세션에 누적 diff 전체를 다시 읽고 있었다.
- **안전장치:** 이어 쓰면 앞선 판단에 끌려갈 수 있다. 승인 직전 전체 재검수는 넣지 않았다(반려 한 번만 있어도 비용이 늘어남). 통합 뒤 최종 검수(FINAL_QA)가 새 세션으로 전체를 다시 본다.
- 이미지·출력 스키마 옵션은 `resume`/`fork` 하위 명령 뒤에 둔다(`codex exec resume --help` 기준).

## 2026-11-02 — 반려 한도 5 → 3

- 한 회차는 dev + 테스트 + QA + GPT 검수로 비싸다. 같은 지적이 반복되는 루프는 마스터가 일찍 개입하는 편이 싸다. smoke 실행의 막힘도 결국 사람이 풀었다. 하네스 반려(테스트 실패 등)도 한도에 포함된다.

## 2026-11-02 — Playwright MCP 버전 고정

- `@playwright/mcp@latest` → `@0.0.83`(2026-09-28 출시). QA 시작마다 레지스트리 조회가 사라지고 공급망 위험이 준다. 0.0.84는 출시 이틀째라 쓰지 않았다.

## 2026-11-02 — 검수 diff에서 잠금 파일 제외

- git은 경로를 알파벳순으로 나열해 `package-lock.json`이 `src/`보다 앞에 온다. 6만 자 한도를 잠금 파일이 채우면 검수자가 코드를 못 보고 승인할 수 있었다. 잠금 파일을 빼고, 잘리면 못 본 파일 목록을 붙인다.

## 2026-11-02 — 에이전트를 사용자 설정과 분리

- 파이프라인 에이전트는 `--setting-sources project,local --strict-mcp-config`. 사용자 플러그인(`claude-mem` 등)과 훅이 저장소 내용을 읽는 에이전트에 붙지 않게 한다. 스킬 실행만 예외([security.md](security.md)).

## 2026-11-02 — 스킬 실행: 권한 승인과 중단

- 처음엔 권한 없이 실행하고, 거부되면 사람 승인 뒤 같은 세션을 실행 폴더 안 편집만 허용해 잇는다. 셸 승인은 넣지 않았다(PC 전체 명령 실행이 되므로).
- 실행은 비동기(시작 즉시 `202`, 화면은 3초마다 조회)로 바꿔 중단을 가능하게 했다. 한 번에 하나만.

## 2026-11-02 — 루틴은 오케스트레이터 안에서

- Windows 작업 스케줄러 대신 서버 안 30초 스케줄러. 시스템 설정을 바꾸지 않고 만들기·고치기·지우기가 즉시 반영된다. 대가: 서버가 꺼져 있으면 돌지 않고, 켜질 때 가장 최근 예정분 한 번만 따라잡는다. Vault 계약도 작업 스케줄러는 수동 실행이 안정된 뒤에만 쓰라고 한다.

## 2026-11-02 — 주소에 화면 상태

- 홈의 프로젝트 선택(`#/?project=`)과 관제 화면 패널 탭(`#/run?tab=&sub=`)을 해시 질의로 남긴다. `replaceState`라 라우팅을 다시 타지 않고 뒤로 가기 기록도 쌓지 않는다. 보고서 링크로 원본 메시지에 갈 때는 주소 값을 무시한다(`useHashParam`의 `fromUrl=false`).

## 2026-11-02 — 라이브러리를 Vault 노트로 저장

- **결정:** 브랜드·콘텐츠·아이디어 라이브러리를 브라우저 `localStorage`에서 Vault의 `Libraries/brand|content|ideas`로 옮긴다(`orchestrator/src/vault/library.ts`, `/api/library/:kind[/:file]`). 카드 하나 = Markdown 노트 하나, frontmatter `title`·`status`·`kind`·`tags`·`updated`.
- **이유:** 다른 브라우저·기기에서도 보이고, Obsidian에서 그대로 읽고 고칠 수 있고, Vault의 Git 동기화로 백업된다.
- **충돌:** 수정 요청에 화면이 읽은 `mtimeMs`를 함께 보내 디스크와 다르면 409. Git 병합 충돌은 Obsidian Git이 처리한다.
- **이전:** 각 라이브러리 페이지를 처음 열 때 예전 `localStorage` 항목을 Vault로 만들고(이미 있으면 건너뜀) 브라우저 사본을 지운다.
- 제목을 고쳐도 파일 이름은 그대로 둔다(링크가 깨지지 않게).

## 2026-11-02 — 파이프라인 시작은 항상 사람이

- **결정:** 스펙 승인은 실행을 시작하지 않는다. `POST /api/pipeline/start`(대시보드 상단 [파이프라인 시작]·결정 큐)로만 시작하고, `POST /api/pipeline/stop`으로 정지한다. 상태는 `STATE_CHANGE {pipeline: 'running'|'stopped'}` 이벤트로 남는다.
- **정지 의미:** 지금 도는 에이전트 작업은 끝까지 두고 새 태스크·다음 단계는 시작하지 않는다(중간에 끊으면 작업 폴더가 반쯤 바뀐 채 남는다).
- **재시작:** 서버를 다시 켜면 `running`일 때만 이어서 돈다. 이 기능 이전 프로젝트는 상태가 없으므로 시작 전으로 보고 사람의 시작을 기다린다.
- 시작은 실제 Claude·GPT 호출로 비용이 들어 한 번 더 확인한다.

## 2026-11-02 — 파이프라인 설계·완수 기준은 Vault에

- `vault.pipeline`(기본 `01 Projects/[진행] NEWTEAMs AI Agent Studio/파이프라인`)의 `00 파이프라인 설계`와 역할에 맞는 단계 노트(01–08)를 매 에이전트 프롬프트 끝에 붙인다(`contextBuilder.ts` `pipelineNoteFor`). 매번 새로 읽으므로 Obsidian에서 고친 기준이 다음 실행에 바로 반영된다. 노트당 8천 자까지.

## 2026-11-02 — 스킬 고정 목록은 사용자 홈에

- 고정 목록을 프로젝트 폴더(`projects/<이름>/skill-runs/pinned.json`, git에서 빠짐)에서 `~/.newteams/pinned-skills.json`으로 옮겼다. 프로젝트를 바꾸거나 다시 만들어도 사라지지 않는다.
- 저장은 직전 본을 `.bak`으로 남기고 임시 파일→이름 바꾸기. 파일이 깨지면 기본값으로 덮지 않고 `.bak`을 읽는다.
- 대시보드는 고정 목록을 읽기 전에는 ☆을 누를 수 없다(읽기 실패 상태에서 누르면 빈 목록 위에 저장돼 실제 목록이 지워지던 버그).

## 2026-11-02 — 전문가 그래프: 검색이 아니라 순회

- **결정:** Vault `wiki/전문가 그래프/`(설정 `vault.graph`)의 노트를 노드로, 작업 노트 frontmatter의 정해진 6개 키(`applies_to`·`knowledge`·`process`·`tools`·`done`·`requires`)를 엣지로 읽는다(`orchestrator/src/context/expertGraph.ts`). 에이전트는 자기 실행 키(plan·dev·qa·review·report…)의 작업 노드에서 시작해 지식→과정→도구→기준→선행 작업의 기준 순으로 읽는다.
- **이유:** 임베딩 검색은 무엇이 들어갔는지 설명할 수 없다. 고정 경로 순회는 매번 같고, 프롬프트에 "읽은 경로"를 함께 남겨 반려 원인이 문서 부족인지 가를 수 있다.
- **단위:** 직군이 아니라 작업. 지식·도구 노드는 분야 사이에 공유한다. 새 분야는 `_템플릿/`으로 작업 노드부터.
- **상한:** 노드당 3천 자, 전체 1만 2천 자. 그래프에 해당 작업이 없으면 기존 `파이프라인/` 단계 노트를 쓴다.
