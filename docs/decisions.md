# 결정 기록

코드만 보고는 이유를 알기 어려운 결정을 날짜순으로 남긴다. 새 결정은 아래에 덧붙인다.

## 2026-11-02 — 검수 세션 이어 쓰기

- **결정:** 태스크 검수 2회차부터 GPT 검수자는 같은 Codex 세션을 이어(`codex exec resume`) 지난 검수 이후 diff만 받는다(`prompts/reviewer-followup.md`). OpenAI 예비 실행기는 세션을 모르므로 요청마다 전체 프롬프트(`freshPrompt`)를 함께 두고, 넘어갈 때 그것을 보낸다. 세션 ID를 못 받은 회차 다음은 다시 전체 검수.
- **이유:** smoke 실행 실측 캐시 비율이 dev 94.5%, 검수자 12.7%. 검수자는 매 회차 새 세션에 누적 diff 전체를 다시 읽고 있었다.
- **안전장치:** 이어 쓰면 앞선 판단에 끌려갈 수 있다. 승인 직전 전체 재검수는 넣지 않았다(반려 한 번만 있어도 비용이 늘어남). 통합 뒤 최종 검수(FINAL_QA)가 새 세션으로 전체를 다시 본다.
- 이미지·출력 스키마 옵션은 `resume`/`fork` 하위 명령 뒤에 둔다(`codex exec resume --help` 기준).

## 2026-11-02 — 반려 한도 5 → 3

- 한 회차는 dev + 테스트 + QA + GPT 검수로 비싸다. 같은 지적이 반복되는 루프는 마스터가 일찍 개입하는 편이 싸다. smoke 실행의 막힘도 결국 사람이 풀었다. 하네스 반려(테스트 실패 등)도 한도에 포함된다.

## 2026-11-02 — Playwright MCP 버전 고정

- `@playwright/mcp@latest` → `@0.0.83`(2026-09-28 출시). QA 시작마다 레지스트리 조회가 사라지고 공급망 위험이 준다. 0.0.84는 출시 이틀째라 쓰지 않았다.

## 2026-11-02 — 검수 diff에서 잠금 파일 제외

- git은 경로를 알파벳순으로 나열해 `package-lock.json`이 `src/`보다 앞에 온다. 6만 자 한도를 잠금 파일이 채우면 검수자가 코드를 못 보고 승인할 수 있었다. 잠금 파일을 빼고, 잘리면 못 본 파일 목록을 붙인다.

## 2026-11-02 — 에이전트를 사용자 설정과 분리

- 파이프라인 에이전트는 `--setting-sources project,local --strict-mcp-config`. 사용자 플러그인(`claude-mem` 등)과 훅이 저장소 내용을 읽는 에이전트에 붙지 않게 한다. 스킬 실행만 예외([security.md](security.md)).

## 2026-11-02 — 스킬 실행: 권한 승인과 중단

- 처음엔 권한 없이 실행하고, 거부되면 사람 승인 뒤 같은 세션을 실행 폴더 안 편집만 허용해 잇는다. 셸 승인은 넣지 않았다(PC 전체 명령 실행이 되므로).
- 실행은 비동기(시작 즉시 `202`, 화면은 3초마다 조회)로 바꿔 중단을 가능하게 했다. 한 번에 하나만.

## 2026-11-02 — 루틴은 오케스트레이터 안에서

- Windows 작업 스케줄러 대신 서버 안 30초 스케줄러. 시스템 설정을 바꾸지 않고 만들기·고치기·지우기가 즉시 반영된다. 대가: 서버가 꺼져 있으면 돌지 않고, 켜질 때 가장 최근 예정분 한 번만 따라잡는다. Vault 계약도 작업 스케줄러는 수동 실행이 안정된 뒤에만 쓰라고 한다.

## 2026-11-02 — 주소에 화면 상태

- 홈의 프로젝트 선택(`#/?project=`)과 관제 화면 패널 탭(`#/run?tab=&sub=`)을 해시 질의로 남긴다. `replaceState`라 라우팅을 다시 타지 않고 뒤로 가기 기록도 쌓지 않는다. 보고서 링크로 원본 메시지에 갈 때는 주소 값을 무시한다(`useHashParam`의 `fromUrl=false`).
