# 텔레그램 연결 안내

`orch serve <name>`을 실행하는 PC가 알림을 보내고 명령을 받는다. PC가 켜져 있고 절전 상태가 아니어야 하며, serve 프로세스와 인터넷 연결이 유지되어야 한다. 인바운드 포트를 열 필요는 없다. 아래 CLI 예시는 저장소의 `orchestrator/`에서 실행한다. `orch`를 연결해 두지 않았다면 `orch` 대신 `npx tsx src/cli.ts`를 쓴다.

## 1. BotFather에서 봇 만들기

텔레그램의 공식 BotFather 계정 `@BotFather`에서 `/newbot`을 입력하고 이름과 사용자 이름을 정한다. 받은 토큰은 **사용자 본인만 터미널에서 입력**한다. 토큰을 Codex 대화에 붙여 넣거나 에이전트에게 전달하지 않는다. 설정 JSON, `.env` 파일, 저장소, 스크린샷, 작업 보고서에도 남기지 않는다. 노출되었다면 BotFather에서 토큰을 재발급한다.

## 2. 환경 변수 입력하기

PowerShell 7에서는 입력을 가려 현재 터미널에만 설정할 수 있다. 다음 명령의 프롬프트에서 직접 입력하며, 토큰 자체를 명령줄에 쓰지 않는다.

```powershell
$env:TELEGRAM_BOT_TOKEN = Read-Host 'BotFather 토큰' -MaskInput
$env:TELEGRAM_CHAT_ID = '0'
```

두 변수가 **모두** 있어야 봇이 시작된다. chat id를 모르는 동안에는 위처럼 임시 값 `0`을 사용한다. 하나라도 없으면 `텔레그램: 꺼짐 (환경 변수 없음)`으로 시작하고 HTTP 서버는 계속 사용할 수 있다.

이 설정은 해당 터미널과 그 터미널에서 시작하는 프로세스에만 적용된다. 새 터미널에서는 다시 입력한다. 영구 보관이 필요하면 사용자가 Windows의 사용자 환경 변수 편집 화면에서 두 값을 직접 등록할 수 있다. 등록 후 새 터미널을 열어야 반영된다. 이 값은 운영체제에 저장되므로 공유 PC에서는 현재 세션 설정을 권장한다. 환경 변수 목록이나 값을 출력해 확인하지 않는다.

## 3. chat id 확인하고 다시 시작하기

```powershell
orch serve <name>
```

`텔레그램: @사용자이름 연결됨`이 나온 **뒤에**, 방금 만든 봇과의 개인 대화에서 새 메시지를 보낸다. 처음 시작할 때 과거 메시지는 건너뛰므로 연결 전에 보낸 메시지는 발견용으로 쓰이지 않을 수 있다. 콘솔의 `텔레그램: 허용되지 않은 채팅 <숫자>`에서 본인 대화의 숫자를 확인한다. 허용되지 않은 채팅에는 봇이 답하지 않으며 같은 id의 경고는 프로세스당 한 번만 표시된다.

`Ctrl+C`로 serve를 종료하고 같은 터미널에서 실제 chat id를 입력한 뒤 다시 시작한다. 숫자의 부호까지 그대로 입력한다. 그룹 채팅 id를 쓰면 그 그룹의 모든 멤버가 승인·건너뛰기·/ask를 할 수 있습니다. 개인 채팅 id를 권장합니다.

```powershell
$env:TELEGRAM_CHAT_ID = Read-Host '내 채팅의 숫자 id' -MaskInput
orch serve <name>
```

토큰 하나당 polling 중인 serve 프로세스는 **하나만** 실행한다. 다른 터미널이나 PC에서 같은 봇을 실행 중이라면 먼저 종료한다. 프로젝트를 바꿀 때도 기존 serve를 종료한다.

CLI에서 `Ctrl+C`나 `SIGTERM`으로 종료하면 해당 CLI가 시작한 AI CLI·검사 명령의 자식 프로세스 트리도 종료한다. HTTP·봇 종료에는 최대 3초를 기다린 뒤 프로세스를 끝내며, 기존 raw 로그와 상태 파일을 보존한다. 진행 중이던 작업은 다음 `serve`에서 복구한다. 운영체제가 자식 종료를 거부하면 `자식 프로세스 종료 실패`를 표시하고 부모 프로세스를 유지하므로 해당 터미널에서 원인을 확인한다.

## 4. 연결 확인

serve를 잠시 종료한 뒤 두 환경 변수가 설정된 터미널에서 실행한다.

```powershell
orch telegram-check
```

이 명령은 실제 Telegram API의 `getMe`를 호출하고 지정한 대화에 `연결 확인 ✓` 메시지 한 건을 보낸 뒤 종료한다. polling이나 AI 작업은 시작하지 않는다. 성공 출력은 `텔레그램: @사용자이름 연결됨`이다. 다시 `orch serve <name>`을 실행하고 연결 후 `/status`를 새로 보내 응답도 확인한다.

## 5. 알림, 버튼, 명령

| 알림 | 기본 소리 | 버튼/동작 |
|---|---|---|
| 스펙 초안 | 소리 | 승인 → 정말 승인, 대시보드 링크(설정 시) |
| 교착으로 사람 필요 | 소리 | 지침 쓰기, 건너뛰기 → 정말 건너뛰기, 자세히 |
| 로그인 필요·API 상한 | 소리 | PC에서 조치 후 재개 |
| 워크플로 오류 | 소리 | 자세히 |
| 완료 | 소리 | 보고서 |
| 단계 변경·일시정지·재개 | 무음 | 상태 요약 |
| 태스크 승인 | 기본 꺼짐 | 켜면 무음으로 묶어 전송 |

별도 병합 알림은 현재 지원하지 않는다. 지침은 **지침 쓰기**를 누르고, 봇이 보내는 답장 요청 메시지에 답장한다. 이미 처리된 요청에 답하면 `이미 처리됨`으로 표시된다. 건너뛰기는 해당 태스크와 그에 의존하는 작업에 영향을 줄 수 있으므로 내용을 확인한다.

| 명령 | 동작 |
|---|---|
| `/start`, `/help` | 명령 안내 |
| `/status` | 단계, 진행/반려/주의, 일시정지 요약 |
| `/tasks` | 태스크 보드 요약 |
| `/report` | 최종 보고서 요약 |
| `/resume` | 로그인 등 필요한 조치 후 재개 |
| `/ask <질문>` | 사용량 안내와 확인 버튼을 먼저 표시하고 확인 후 로그 질의 실행 |

`/ask`는 AI 사용량을 쓴다. 확인 버튼은 10분 뒤 만료되고 같은 확인을 반복 실행하지 않는다. 질문 없이 `/ask`만 보내면 사용법을 안내한다. 오래 걸리는 질의 중에도 다른 명령을 받을 수 있다.

텔레그램에는 요약만 보낸다. 코드 블록, diff 본문, 원본 프롬프트 경로는 필터링한다. 파일 내용과 원본 프롬프트를 확인할 때는 대시보드를 사용한다. **자세히**를 명시적으로 눌렀을 때만 해당 태스크의 최신 QA 회차 캡처 한 장을 추가로 보낸다. 텍스트와 캡처는 텔레그램 서버에 전송된다.

업데이트 offset은 명령 실행 **전에** 체크포인트로 저장한다. 이 방식은 같은 명령의 재실행을 막지만, 체크포인트 직후 프로세스가 종료되면 아직 실행하지 않은 명령이 누락될 수 있다. 상태를 확인하고 필요한 명령을 다시 입력한다. 재시작하면 진행 중이던 확인과 지침 답장 연결은 사라진다. `/ask` 질문을 새로 보내거나 원래 알림의 승인/건너뛰기/지침 쓰기 버튼을 다시 눌러 새 확인·답장 요청을 만든다.

## 6. 선택 설정

비밀값을 제외한 설정은 기존 CLI JSON에 추가한다. 예:

```json
{
  "telegram": {
    "quietHours": { "start": "23:00", "end": "07:00" },
    "heartbeatMinutes": 30,
    "batchSeconds": 30,
    "notifyTaskApprovals": false,
    "dashboardUrl": "https://my-pc.example-tailnet.ts.net"
  }
}
```

```powershell
orch --config config.json serve <name>
```

`quietHours`는 PC의 로컬 시간 기준이다. 해당 시간대의 소리 알림을 무음으로 보내고 끝나면 요약한다. `null`이면 꺼진다. `heartbeatMinutes`는 `0`이면 꺼지고, 켤 때는 5~1440분이다. 무음 알림은 기본 30초간 묶인다. `dashboardUrl`은 선택 사항이며 `null`이면 링크가 없다. Tailscale을 쓰는 경우 사용자가 자신의 기기에만 접근 가능한 실제 주소로 바꾼다. 이 설정만으로 대시보드가 외부에 공개되지는 않는다. HTTP 서버는 계속 `127.0.0.1`에 바인딩된다.

## 7. 문제 해결

알림이 오지 않으면 로컬 상태를 확인한다. 기본 포트는 4317이며 별도 포트를 설정했다면 바꾼다.

```powershell
Invoke-RestMethod http://127.0.0.1:4317/api/telegram
```

| 상태/증상 | 확인할 것 |
|---|---|
| `off` | serve를 시작한 터미널에 두 환경 변수가 모두 있는지 확인하고 재시작 |
| `connecting` | 초기 연결 진행 중. 네트워크와 PC 절전 상태 확인 |
| `error` | `lastError` 확인. 토큰 재발급 여부, 인터넷, 같은 토큰의 다른 polling 프로세스 확인 |
| `connected`지만 명령 응답 없음 | 연결 후 새 메시지를 보냈는지, 실제 chat id로 재시작했는지 확인 |
| 알림이 늦거나 무음 | 조용한 시간과 batch 설정 확인 |
| 확인 만료·재시작 후 답장 미작동 | 버튼을 다시 누르거나 질문을 다시 보내 새 요청 생성 |

`GET /api/telegram`은 `state`, 봇 사용자 이름, 최근 성공 시각, 오류 요약만 반환한다. 토큰이나 허용 chat id는 반환하지 않는다. 연결 오류가 나도 HTTP 서버와 워크플로는 계속 실행되고 봇은 백그라운드에서 재연결한다. 종료할 때는 `Ctrl+C`나 SIGTERM으로 서버를 닫아 polling 중단과 알림 정리를 수행한다.
